The whole course is one question

Which machine can check whether a word belongs to a club? Every lecture, from 1 to 12, adds a little more memory to the machine and asks what it can do now.

In one sentence

A language is a set of strings. A machine reads a string and says accept or reject. The course compares machines by how much they can remember.

The four words you need first

Alphabet Σ = {a, b}
The letters we are allowed to use. Like the keys on a tiny keyboard with only two keys.
String: abba, b, aaa
A string is just letters in a row, finite length. "abba" uses only keys a and b, so it is a string over Σ.
ε = the empty string, length 0
Pressing no keys at all is still a string. Its length is 0. We write it ε (epsilon) so we can see it.
Language = a set of strings, for example {w | w contains 11}
Think of a club with a rule. "contains 11" is the rule. 0110 gets in (it has 11). 0101 does not.
∅ (empty language) ≠ {ε}
∅ is a club with nobody in it. {ε} is a club with exactly one member: the empty string. One member is not zero members, so they are different.
Σ* = all strings over Σ
The star means "any number of letters, including none". So Σ* = {ε, a, b, aa, ab, ba, bb, aaa, ...}.

Each step up the ladder gives the machine more memory. More memory means it can check more languages.

Lectures 01–02 · Introduction, motivation, finite automata

The machine with no notebook

A finite automaton remembers only one thing: which state it is in right now. That tiny memory is enough for a surprising number of problems.

Why this course exists

The lecture opens with three big questions about computers:

Computability: what can be computed at all?
Some problems have no program that solves them, ever. Studied 1930s–1950s (finite automata, Turing machines).
Complexity: how fast, with how much memory?
Example from the slide: factoring 15 = 3 × 5 is easy, but a number with hundreds of digits is very hard. A problem can be computable but still hard. Studied 1960s–today. Measures: time and space.
Languages and automata: which model of computation should we use?
That is the part of the course you are in now.
A computational model = a simplified mathematical description of a computer
It tells us: what information it can hold, what operations it can do, how its state changes, and which problems it can solve.

Why learn it (from the slide): it has big ideas, it helps in practice (for example designing a new programming language), and it trains you to think and write precisely and to know when a problem is not solved yet.

The motivation puzzle: man, wolf, goat, cabbage

A man must cross a river with a wolf, a goat and a cabbage. The boat holds the man plus at most one item. Wolf alone with goat: the goat is eaten. Goat alone with cabbage: the cabbage is eaten. The lecture solves it by drawing every situation as a state and every crossing as an arrow. That drawing is a finite automaton. The sequence of moves is a string; a string that reaches "everyone across" is accepted.

Solution: g m w g c m g (take goat, come back, take wolf, bring goat back, take cabbage, come back, take goat). Wrong moves lead to "dead" states, which the lecture adds as "all wrong moves".

How a DFA works

The board game

Circles are squares on a board. You stand on the circle with the arrow pointing into it (the start state). Read the input one letter at a time. For each letter, follow the arrow that has that letter on it. When the letters run out, look at where you are standing. Double circle = accept. Single circle = reject.

This machine is M1 from the lecture. It accepts exactly the strings that contain 11. Try 01101 (accept) and 00101 (reject), the two examples on the slide.

q1 = "I have not seen anything useful yet"
Every state means a memory. Reading 0 here keeps you in q1 because a 0 does not start a "11".
q2 = "the last letter was 1"
One more 1 would make 11. A 0 breaks it, so 0 sends you back to q1.
q3 = "I have seen 11" (accept)
Once 11 appeared, nothing can erase it, so q3 loops to itself on 0 and 1.
A = L(M1) = {w | w contains 11}
"L(M1)" means the language of M1: all strings M1 accepts. We say "M1 recognizes A".

The formal definition (5-tuple)

The exam always asks for this. It is the picture written as a list of five things.

M = (Q, Σ, δ, q0, F)
Five parts, always in this order. "5-tuple" just means a list of 5 things.
Q = {q1, q2, q3}
Q = the set of all states = all the circles. Must be finite (that is the "finite" in finite automaton).
Σ = {0, 1}
The alphabet: the letters written on the arrows.
δ : Q × Σ → Q
δ (delta) is the transition function. Give it a state and a letter, it gives back ONE state. δ(q, a) = r means "an arrow labeled a goes from q to r".
q0 = q1
The start state: the circle with the arrow coming in from nowhere.
F = {q3}
F = the set of accept states = the double circles. F can have zero, one or many states.

How to read the table: row = where you are, column = letter you read, cell = where you go. Every row has exactly one entry per letter. That is what "deterministic" means.

Accepting, said precisely

M accepts w = w1w2…wn if there are states r0, r1, …, rn with
r0…rn is the list of squares you stand on during the game. n letters means n+1 squares (you also count where you started).
1) r0 = q0
You begin at the start state.
2) ri = δ(ri−1, wi) for 1 ≤ i ≤ n
Each next square is decided by the previous square and the letter just read. That is just "follow the arrow".
3) rn ∈ F
The last square is a double circle.
Definition: a language is regular if some finite automaton recognizes it.
So to prove a language is regular, you just show one DFA for it. That is all.

More examples from the slide: B = {w | w has an even number of 1s} is regular (make the automaton for practice: two states, "even so far" and "odd so far"). C = {w | w has equal numbers of 0s and 1s} is not regular. We prove it in Lecture 6.

Recipe: design a DFA

Recipe — design a DFA (Assignment 1, exam B.1)
  1. Ask: what do I need to remember while reading, to decide at the end?
  2. Each different thing you might remember = one state. Give it a name that says the memory.
  3. Start state = what you remember before reading anything.
  4. Accept states = the memories that mean "yes".
  5. From every state draw exactly one arrow for every letter. If a string can never be fixed, send it to a dead state (trap) that loops on everything.
  6. Test with a yes-string, a no-string, and ε.
  7. Write the 5-tuple and the δ table.

Closure: combining two regular languages

In one sentence

"Closed under union" means: if A1 and A2 are regular, then A1 ∪ A2 is regular too. We prove it by building one machine that runs both machines at the same time.

The regular operations from the lecture:

Union: A ∪ B = {w | w ∈ A or w ∈ B}
Join the two guest lists. A = {good, bad}, B = {boy, girl} gives {good, bad, boy, girl}.
Concatenation: A ∘ B = {xy | x ∈ A and y ∈ B}
One word from A glued in front of one word from B: {goodboy, goodgirl, badboy, badgirl}.
Star: A* = {x1…xk | each xi ∈ A, k ≥ 0}
Glue any number of words from A, including zero words. Zero words gives ε, so ε ∈ A* always. A* = {ε, good, bad, goodgood, goodbad, …}.

The product construction (two machines in one)

M1 = (Q1, Σ, δ1, q1, F1) recognizes A1; M2 = (Q2, Σ, δ2, q2, F2) recognizes A2
These exist because A1 and A2 are regular (definition of regular).
Q = Q1 × Q2 = {(q, r) | q ∈ Q1, r ∈ Q2}
Each new state is a PAIR: "where M1 is" and "where M2 is". Like two fingers on two boards at once.
q0 = (q1, q2)
Both fingers start on their own start states.
δ((q, r), a) = (δ1(q, a), δ2(r, a))
Read one letter: move BOTH fingers, each on its own board.
F = F1 × F2 ✗ NO — that gives intersection
F1 × F2 means both fingers on double circles = in A1 AND in A2. That is ∩, not ∪.
F = (F1 × Q2) ∪ (Q1 × F2)
Union needs AT LEAST ONE finger on a double circle: M1 accepts (M2 anywhere) or M2 accepts (M1 anywhere).
|Q| = k1 × k2 (Check-in 1.1: answer c)
Number of pairs = choices for the first × choices for the second.
Exam versions
  • Intersection (2024 B.3): same pairs, F = pairs where both are accept.
  • Symmetric difference (2025 Q.2): F = pairs where exactly one is accept. Closure proof: S1 ⊖ S2 = (S1 ∩ S̄2) ∪ (S2 ∩ S̄1), and regular languages are closed under ∩, ∪ and complement (complement = swap accept and non-accept states of a DFA).

Concatenation is harder (last slide of the lecture): the machine must accept w if w = xy with M1 accepting x and M2 accepting y. But where do we split w? A DFA cannot know. This is exactly why Lecture 3 introduces nondeterminism.

Lectures 03–04 · Regular languages II: nondeterminism

The machine that can clone itself

An NFA is a DFA with three new freedoms. They make machines much easier to design, and they do not make the machine stronger.

In one sentence

When an NFA has a choice, it splits into copies that try every choice at the same time. If any copy ends on a double circle, the string is accepted.

The three new features

1. A state may have 0, 1 or many arrows for the same letter
Many arrows: the machine clones itself, one copy per arrow. Zero arrows: that copy dies quietly.
2. ε-arrows (free moves)
An arrow labeled ε can be taken without reading any letter. A copy standing next to it also appears on the other side for free.
3. Accept if some path ends on an accept state
It is enough that one copy wins. The other copies can die or end on normal circles.

Three ways to think about it (from the slide): computational = fork parallel threads; mathematical = a tree of branches, accept if any branch accepts; magical = the machine always guesses the right way. Nondeterminism does not correspond to a physical machine we can build, but it is very useful mathematically.

Formal definition

NFA N = (Q, Σ, δ, q0, F)
Same five parts as a DFA. Only δ is different.
δ : Q × Σε → 𝒫(Q)
Σε = Σ ∪ {ε}: δ also accepts ε as an input (free moves). 𝒫(Q) = the power set = all subsets of Q. So δ gives back a SET of states (maybe empty), not one state.
Example on the slide: δ(q1, a) = {q1, q2}, δ(q1, b) = ∅
From q1 an a leads to two places (clone!). A b leads nowhere (that copy dies).

NFAs are often much smaller

Example 2: strings over {0,1} with a 1 in the third position from the end. The NFA has 4 states: loop on 0,1 at q1, then guess "this 1 is the one" and read exactly two more letters. The DFA needs 8 states (q000 … q111), because it must remember the last three letters.

Example 3: strings over {0} whose length is a multiple of 2 or 3. Start with two ε-arrows: one into a 2-cycle, one into a 3-cycle. The machine guesses which test to run.

NFA → DFA (subset construction)

Theorem

If an NFA recognizes A, then A is regular. Idea: the DFA keeps track of the set of states where the NFA copies are standing.

Q′ = 𝒫(Q)
Each DFA state is a set of NFA states, for example {q3, q7}. If the NFA has n states there are 2n subsets (Check-in 2.2: answer 2n).
δ′(R, a) = {q ∈ Q | q ∈ δ(r, a) for some r ∈ R}
From a set R, reading a: collect everywhere ANY member of R can go on a. That is the new set.
q0′ = {q0}
At the start, all copies (just one) are on the NFA start. With ε-arrows: take the ε-closure, E(q0).
F′ = {R ∈ Q′ | R intersects F}
A set is accepting if at least one of its members is an NFA accept state (one winning copy is enough).
Recipe — NFA → DFA by table (Tutorial 3, every midterm)
  1. Write the NFA table: one row per state, one column per letter (and ε if there are ε-arrows).
  2. DFA start = {start} (or its ε-closure).
  3. For the newest set and each letter: union of where every member goes, then add the ε-closure. If this set is new, give it a row.
  4. Repeat until no new set appears. Only sets you actually reach get a row; that gives the minimum number of states the hint asks for.
  5. ∅ is a dead state (qΦ) that loops on every letter.
  6. Accept = every set that contains an NFA accept state. Draw it.

Closure again, now easy

With nondeterminism the closure proofs become drawings. Given NFAs N1 and N2:

Union A1 ∪ A2: a new start state with ε-arrows to both old starts
The machine clones itself at the very beginning: one copy runs N1, one runs N2. If either accepts, the union accepts. ("Massive parallelism vs perfect guessing".)
Concatenation A1A2: ε-arrows from every accept state of N1 to the start of N2; only N2's accept states stay accepting
This answers "where do I split w?" from Lecture 1: whenever N1 could stop, a copy jumps to N2 and tries the rest. Some copy guesses the right split.
Star A*: a new start state that is also accepting, ε to the old start, and ε from every accept state back to the old start
The loop back lets you read one word of A, then another, then another. The new accepting start state makes ε accepted (zero words). Without it ε might be rejected.
Lecture 05 · Regular languages III: regular expressions

Writing a language in one line

A regular expression describes a language the way a recipe describes a cake. Lecture 5 proves that regular expressions and finite automata describe exactly the same languages.

In one sentence

A regular expression is built from single letters, ε and ∅, glued together with three operations: ∪ ("or"), concatenation ("then") and * ("repeat any number of times, even zero").

The building blocks

Atomic: a (for a ∈ Σ), ε, ∅
The smallest pieces. "a" means the language {a}. ε means {ε}. ∅ means the empty language (no strings at all).
Composite: R1 ∪ R2, R1R2, R1*
Bigger expressions are made from smaller ones using only these three operations.
(0 ∪ 1)* = Σ*
0 ∪ 1 means "one letter, 0 or 1". The star repeats that any number of times, so you get every string over {0,1}.
Σ*1 = all strings that end with 1
Anything at all (Σ*), then a 1 at the very end.
Σ*11Σ* = all strings that contain 11 = L(M1)
Anything, then 11, then anything. This is the same language as the DFA M1 from Lecture 1. Same language, two descriptions.
Extra (not on the slides, but you need it)

Order of operations: * first, then concatenation, then ∪. Like powers, then ×, then +. So ab* = a(b*), not (ab)*. And a ∪ bc = a ∪ (bc).

Simplifying rules (Assignment 3 asks to "fully simplify"): R ∪ ∅ = R · Rε = R · R∅ = ∅ · ∅* = ε · ε* = ε · (R*)* = R* · R ∪ R = R · RR* = R⁺ (one or more).

Regex → NFA

Theorem

If R is a regular expression and A = L(R), then A is regular. Proof: turn R into an NFA piece by piece.

R = a → two states, one arrow labeled a
The machine must read exactly one a and stop on an accept state.
R = ε → one state that is start and accept
Accepts without reading anything. That is exactly the string ε.
R = ∅ → one state that is NOT accepting
It can never accept, so its language is empty.
R1 ∪ R2, R1R2, R1* → use the closure constructions
The three pictures at the end of Lecture 3–4: new start with ε to both (∪), ε from accepts of the first to the start of the second (∘), new accepting start plus ε loops back (*).

DFA → Regex (state elimination)

Theorem

If A is regular, then A = L(R) for some regular expression R. So DFAs, NFAs and regular expressions are all equivalent.

The new idea: GNFA

GNFA = an NFA whose arrows are labeled with whole regular expressions
A normal arrow reads one letter. A GNFA arrow labeled "ab*" reads any string that matches ab* in one jump.
Special form: one accept state, different from the start
We add a new start s and a new accept a, so that removing states never touches them.
One arrow from every state to every state, except: start only has arrows going out, accept only has arrows coming in
Missing arrows are labeled ∅ (no way through). Two arrows between the same pair become one arrow with ∪.
Lemma: every GNFA G has an equivalent regex R. Proof by induction on k = number of states
Basis k = 2: only s and a are left, with one arrow r. Then R = r. Step: turn a k-state GNFA into an equivalent (k−1)-state GNFA by removing one state.
Recipe — remove one state x (the "in | out" table from Tutorial 5)
  1. Add a new start S with ε to the old start, and a new final F with ε from every old accept state.
  2. Pick a state x (not S, not F). Write its table: in = states with an arrow into x, out = states x has an arrow to.
  3. For every pair (qi in, qj out) the new arrow qi → qj is r1(r2)*r3 ∪ r4.
  4. r1 = label qi→x, r2 = loop on x (skip the star part if x has no loop), r3 = label x→qj, r4 = the old direct arrow qi→qj (skip "∪ r4" if there was none).
  5. Delete x. Repeat until only S → F is left. Its label is the answer.
qi —r1→ x ⟲r2 —r3→ qj becomes qi —r1r2*r3 ∪ r4→ qj
Every old path through x was: enter with r1, go around the loop any number of times (r2*), leave with r3. Or skip x completely with r4. The new label lists both ways.

s→a: a(aa∪b)* · s→3: a(aa∪b)*ab ∪ b · 3→a: (ba∪a)(aa∪b)* ∪ ε · 3→3: (ba∪a)(aa∪b)*ab ∪ bb
Same formula four times. "∪ ε" on 3→a is there because 3 already had its own ε-arrow to a. "∪ bb" because 3 already had the loop bb.
Remove 3: s→a = (a(aa∪b)*ab ∪ b)((ba∪a)(aa∪b)*ab ∪ bb)*((ba∪a)(aa∪b)* ∪ ε) ∪ a(aa∪b)*
r1 = s→3, r2 = loop on 3, r3 = 3→a, r4 = the old s→a. Long, but every piece comes from one arrow. That is the final answer on the slide.
Watch out
  • Never forget "∪ r4" when there already was a direct arrow.
  • Two loops on the same state merge into one loop with ∪ inside one star: (r ∪ s)*, not r* ∪ s*.
  • The order you remove states changes how the answer looks, not the language. Any order is correct.
Lecture 06 · Regular languages IV: non-regular languages

How to prove that no DFA exists

This is the chapter most students find hardest. We go slowly: first why a proof is needed, then where the lemma comes from, then why the proof is "by contradiction", then a game, then a fill-in-the-blanks template for the exam.

1. Why we need a proof

To show a language is regular: give a DFA
One working example is enough. Easy.
To show it is not regular: give a proof
You must show that NO DFA in the world works. There are infinitely many DFAs, so you cannot try them all.
"I could not find a DFA" is not a proof
Maybe you were just not clever enough. The lecture shows this with two examples.
B = {w | equal numbers of 0s and 1s}: intuition says not regular, and it is not regular
A DFA cannot count without limit, and B needs counting.
C = {w | equal numbers of 01 and 10 substrings}: intuition says not regular, but C is regular!
0101 ∉ C (two 01s, one 10). 0110 ∈ C (one each). It turns out 01 and 10 always alternate, so C is just "starts and ends with the same symbol (or has length 0 or 1)". Intuition was wrong. Moral: you need a proof.

2. Where the lemma comes from: the repeated room

The story

A house has p rooms. You walk through it and every letter you read moves you to a room. If you read p letters, you visit p + 1 rooms (counting the room you started in). p + 1 visits but only p rooms: you must enter some room twice. That is the pigeonhole principle (Check-in 3.2: answer a).

Entering a room twice means you walked in a circle. A circle can be walked 0 times, 1 time, 2 times, 100 times and you still come out at the same place. So the machine ends in the same state, and gives the same answer. That is "pumping".

3. The lemma, line by line

Pumping lemma (slide)

For every regular language A, there is a number p (the pumping length) such that if s ∈ A and |s| ≥ p, then s = xyz where
1) xyiz ∈ A for all i ≥ 0   2) y ≠ ε   3) |xy| ≤ p

"For every regular language A there is a number p"
p = the number of states of a DFA for A. We do not know it. It just exists.
"if s ∈ A and |s| ≥ p"
Only long strings must be pumpable. Long = at least p letters, so a state repeats.
"s = xyz"
x = before the loop, y = the loop, z = after the loop. Exactly like the picture above.
1) xyiz ∈ A for all i ≥ 0
yi = y written i times. i = 0 removes y. i = 2 doubles it. The result stays in A because the machine ends in the same state.
2) y ≠ ε (same as |y| ≥ 1)
A loop must contain at least one letter. You cannot walk in a circle without taking a step.
3) |xy| ≤ p
The first repeat must happen within the first p letters, because p letters already give p + 1 visits. So the loop is near the START of s. This condition is the secret weapon of every proof.

Informally: A is regular → every long string in A can be pumped and the result stays in A.

4. Why "proof by contradiction"?

The heartbeat idea

Every living person has a heartbeat. This thing has no heartbeat. So it is not a living person. You do not need to check every person in the world.

The lemma says: regular ⟹ pumpable
"Pumpable" is the heartbeat. Every regular language has it.
So: NOT pumpable ⟹ NOT regular
If a language fails the test, it cannot be regular. This is the logic rule "if P then Q" means "if not Q then not P".
We write it as: assume L IS regular … then it must be pumpable … but it is not … contradiction
We pretend the opposite of what we want, follow the rules, and reach something impossible. So the pretending was wrong. That is all "contradiction" means.
Why not prove "not regular" directly?
"Not regular" says something about ALL DFAs at once. The lemma gives us one property all of them share, so we can test that one property instead.
The other direction does NOT work (midterm 2023 A.8)

If a language passes the test (some string can be pumped), that does not prove it is regular. A heartbeat does not prove you are a person (dogs have one too). The pumping lemma can only prove non-regularity.

5. The proof is a game with four moves

Move 1 — the opponent picks p
The opponent claims L is regular. You do not know his p, so your answer must work for any p. That is why exam proofs keep the letter p and never put p = 3.
Move 2 — YOU pick s ∈ L with |s| ≥ p
This is your only clever move. Choose s so that condition 3 traps y inside one block of the same letter.
Move 3 — the opponent splits s = xyz (|xy| ≤ p, |y| ≥ 1)
You do NOT choose the split. You must win against EVERY allowed split.
Move 4 — YOU pick i so that xyiz ∉ L
Usually i = 2 (pump up) or i = 0 (pump down). If you can always do this, L is not regular.
The trick that makes every proof easy

Start s with p copies of the same letter, like 0p1p. Because |xy| ≤ p, both x and y sit inside the first p letters, so y is only 0s. Every split looks the same, and you only have to handle one case.

6. The lecture proofs, every line explained

Example 1: D = {0k1k | k ≥ 0} is not regular

Assume (to get a contradiction) that D is regular.
We pretend the opposite of what we want to prove.
The pumping lemma gives a pumping length p.
Because we assumed D is regular, the lemma applies to D, so this p exists.
Let s = 0p1p.
p zeros then p ones. It is in D (same number of 0s and 1s, with k = p). Its length is 2p, which is ≥ p. So s is a legal choice.
By the lemma, s = xyz with |xy| ≤ p and |y| ≥ 1.
The lemma promises such a split exists. We do not know which one, so we reason about all of them.
Since |xy| ≤ p, x and y contain only 0s. So y = 0k with 1 ≤ k ≤ p.
The first p letters of s are all 0s. xy is at most p letters long and sits at the start, so it is all 0s. k ≥ 1 because y ≠ ε.
Take i = 2: xyyz = 0p+k1p.
Writing y twice adds k more 0s. The 1s are in z and do not change.
p + k ≠ p, so xyyz ∉ D.
k ≥ 1, so there are more 0s than 1s ("excess 0s"). D needs equal numbers.
This contradicts condition 1 of the lemma. So D is not regular. ∎
The lemma said xyyz must be in D. It is not. The only thing we invented was "D is regular", so that must be false.

Example 2: F = {ww | w ∈ {0,1}*} is not regular

Assume F is regular, with pumping length p.
Same opening every time.
First try: s = 0p0p = 02p. Bad choice!
It is in F (w = 0p). But the opponent can choose y = 00: removing or adding 00 keeps an even number of 0s, which is still ww. We cannot win. Try the game above to see it.
Better: s = 0p1 0p1
w = 0p1, so s = ww ∈ F. Length 2p + 2 ≥ p. The 1s act like walls that the pump cannot cross.
|xy| ≤ p ⟹ y = 0k, 1 ≤ k ≤ p, inside the FIRST block of 0s
The first p letters are the first 0-block.
xyyz = 0p+k1 0p1 ∉ F
To be ww, the first half must equal the second half. The halves would have to start the same way, but one block of 0s has p + k zeros and the other has p. They cannot match.
Contradiction. Therefore F is not regular. ∎
Same ending.

Example 3 (closure trick): B = {w | equal 0s and 1s} is not regular

Assume B is regular.
Opening.
0*1* is regular.
It is a regular expression, and every regular expression gives a regular language (Lecture 5).
So B ∩ 0*1* is regular.
Regular languages are closed under intersection (product construction, Lecture 1).
But B ∩ 0*1* = {0k1k} = D
0*1* forces all 0s before all 1s. B forces the counts to be equal. Together: 0k1k.
We already proved D is not regular. Contradiction! So B is not regular. ∎
No pumping needed this time: we reused Example 1.

7. Exam template — fill in the blanks

The 6-line proof
  1. Assume, for contradiction, that L is regular. Let p be its pumping length.
  2. Choose s = ______. Then s ∈ L because ______, and |s| = ______ ≥ p.
  3. By the pumping lemma, s = xyz with |xy| ≤ p and |y| ≥ 1.
  4. Since |xy| ≤ p and the first p symbols of s are all ___, y = ___k with 1 ≤ k ≤ p.
  5. Take i = ___. Then xyiz = ______, which is not in L because ______.
  6. This contradicts the pumping lemma, so L is not regular. ∎
Which i?
  • i = 2 when adding letters breaks the rule (too many a's).
  • i = 0 when removing letters breaks it. Example: na > nb with s = ap+1bp: adding a's keeps "more a's", but removing k ≥ 1 a's gives p+1−k ≤ p, not more than p.
  • bigger i when needed. anbl with n ≤ l ≤ 2n (2025 Q.6): i = 2 fails when k = 1. i = 3 always works. The game shows this.

Opening.

Lecture 07 · Context-free languages I: context-free grammars

Recipes that make strings

Until now every machine checked strings. A grammar does the opposite: it makes them, by replacing symbols step by step.

In one sentence

A grammar starts from one symbol and keeps replacing capital letters (variables) using rules, until only small letters (terminals) are left. Every string you can make this way is in the language of the grammar.

Grammar vs automaton

Grammar = generative description
It tells you how to BUILD the strings of the language.
Automaton = analytical description
It tells you how to CHECK a given string.
Programming languages: defined by a grammar (BNF), checked by a parser
The compiler's parser is the automaton. Automata theory links the two descriptions.

A grammar has 4 parts: G = (V, T, S, P)

V
Variables (non-terminals): the symbols that still get replaced. Usually capital letters.
T
Terminals: the final letters of the string. They never get replaced.
S
Start symbol: where every derivation begins.
P
Productions (rules), like A → aA.

Example 1 (slide)

V = {S, A, B}, T = {a, b}, start S
Read the parts straight from the definition.
P = {S → A, S → B, B → bB, A → aA, A → ε, B → ε}
S chooses: become A or become B.
A ⇒ aA ⇒ aaA ⇒ aa
A → aA adds one a and keeps A. A → ε stops. So A makes any number of a's.
L(G) = a* ∪ b*
S picks A (only a's) or B (only b's). It can never mix them.

The Chomsky hierarchy

TypeGrammarLanguageAutomaton
Type-0UnrestrictedRecursively enumerableTuring machine
Type-1Context-sensitiveContext-sensitiveLinear bounded automaton
Type-2Context-freeContext-freePushdown automaton
Type-3RegularRegularFinite automaton

Higher number = more rules about the grammar = weaker. Type-3 is the weakest (finite automata), Type-0 the strongest (Turing machines). This matches the ladder on the first page.

Regular and linear grammars

Right-linear: every rule is A → xB or A → x
x is a string of terminals. At most one variable, always at the RIGHT end.
Left-linear: every rule is A → Bx or A → x
At most one variable, always at the LEFT end.
Regular grammar = right-linear OR left-linear
The whole grammar must pick one side and keep it in every rule.
G1: S → abS | a is right-linear
The only variable (S) is at the right end of abS.
G2: S → S1ab, S1 → S1ab | S2, S2 → a is left-linear
Every variable is at the left end. Both G1 and G2 are regular grammars.
S → A, A → aB | ε, B → Ab is not regular
A → aB has the variable on the right, B → Ab has it on the left. Each rule alone looks fine, but the grammar mixes sides.
It is a linear grammar
Linear = at most one variable on the right side, anywhere. Every regular grammar is linear; not every linear grammar is regular.
"Test yourself" (Example 3): its language is {anbn | n ≥ 0}
A → aB and B → Ab together give A ⇒ aB ⇒ aAb. So A → aAb | ε in two steps: equal a's on the left and b's on the right.

Derivations

The language of a grammar is every string of terminals you can derive from the start symbol.

Example 1 (slide): S → aAb, aA → aaAb, A → ε
Careful: the rule aA → aaAb has TWO symbols on the left, so this grammar is not context-free. It is still a grammar (unrestricted).
S ⇒ aAb ⇒ aaAbb ⇒ aaaAbbb ⇒ aaabbb
Each ⇒ uses one rule: S → aAb, then aA → aaAb twice, then A → ε. Language: anbn, n ≥ 1.
Example 2: S → AB, A → a, B → b gives L = {ab}
There is only one way to go: S ⇒ AB ⇒ aB ⇒ ab. One string.

Context-free grammars (CFG)

G1: S → 0S1, S → R, R → ε
3 rules. Variables R, S (they appear on the left). Terminals 0, 1 (they appear only on the right). Start variable S (top left).
Rule form: Variable → string of variables and terminals
"Context-free" = the left side is ONE variable alone. You may replace it wherever it is, whatever is around it (its context).
To generate: write the start variable, replace any variable using a rule, repeat until only terminals remain
That final string is generated. L(G) = all strings that can be generated.
S ⇒ 0S1 ⇒ 00S11 ⇒ 00R11 ⇒ 0011
Each 0S1 step adds one 0 on the left AND one 1 on the right, so they always stay equal. L(G1) = {0k1k | k ≥ 0}.

Formal definition

CFG G = (V, Σ, R, S)
Same 4 ideas as (V, T, S, P), with different letters: Σ = terminals, R = rules. Both notations appear in the slides.
rule form: V → (V ∪ Σ)*
Left: one variable. Right: any string of variables and terminals, including ε.
u ⇒ v: one substitution step
u and v are strings of variables and terminals.
u ⇒* v: some number of steps; the chain u ⇒ u1 ⇒ … ⇒ v is a derivation
If u = S it is a derivation of v.
L(G) = {w | w ∈ Σ* and S ⇒* w}
Only strings of terminals count. "00R11" is not in L(G) because R is still there.
A is a context-free language (CFL) if A = L(G) for some CFG G
Same shape as "regular = some DFA recognizes it".
Leftmost derivation: always replace the leftmost variable
Not on the slides but in every midterm's True/False. In the playground the leftmost variable has a yellow ring.
Chomsky normal form (named in the outline): every rule is A → BC or A → a (plus S → ε allowed)
The slides have no details. Just know the name and the shape: two variables, or one terminal.

Ambiguity

G2: E → E+T | T, T → T×F | F, F → (E) | a
V = {E, T, F}, Σ = {+, ×, (, ), a}, 6 rules, start E. It generates a+a×a, (a+a)×a, a, a+a+a, …
The parse tree carries extra information, like × before +
In G2, × always sits lower in the tree than +, so it is "done first". That is precedence.
A string with two different parse trees is derived ambiguously; the grammar is ambiguous
Two trees = two meanings. Equivalently: two different leftmost derivations.
G3: E → E+E | E×E | (E) | a has the same language as G2, but G3 is ambiguous
L(G2) = L(G3). Ambiguity is about the grammar, not the language.

Recipe: write a CFG (every midterm, part C)

Patterns to copy
  1. Matching from outside in — anbn: S → aSb | ε. Each step adds one a on the left and one b on the right.
  2. Different ratio — anb2n: S → aSbb | ε.
  3. Palindromes — S → aSa | bSb | a | b | ε. Same letter on both ends; the middle may be one letter or nothing.
  4. Union — L1 ∪ L2: S → S1 | S2.
  5. Concatenation — L1L2: S → S1S2.
  6. Anything — X → a | b, and Σ*: A → XA | ε.
  7. Always answer: variables, start variable, terminals, and check one string.

Midterms 2022–2024 C.1 — the statement grammar

Lecture 08 · Context-free languages II: pushdown automata

A DFA with a stack of plates

A finite automaton cannot count without limit, so it cannot check 0k1k. Give it a stack and it can.

In one sentence

A PDA works like an NFA, but it also has a stack: it can put a symbol on top (push) and take the top symbol off (pop). It can never look below the top.

The plates

Think of a pile of plates. You can add a plate on top or take the top one. To count 0s, put one plate down for every 0. For every 1, take one plate away. If the plates run out exactly when the 1s end, the counts were equal.

How to read an arrow: a, b → c

a, b → c
First symbol = what to READ from the input. ε = read nothing.
a, b → c
Second = what must be on TOP of the stack, and gets POPPED. ε = pop nothing (and do not look).
a, b → c
Third = what to PUSH. ε = push nothing.
ε, ε → $
Read nothing, pop nothing, push $. Used at the very start: $ marks the bottom.
ε, $ → ε
Pop $. This is only possible if $ is on top, which means the stack is otherwise EMPTY. That is how a PDA tests "stack empty".

Formal definition: a 6-tuple

PDA = (Q, Σ, Γ, δ, q0, F)
One more part than an NFA: Γ.
Σ = input alphabet, Γ = stack alphabet
They can be different. In 0k1k the input uses {0,1} and the stack uses {0, $}.
δ : Q × Σε × Γε → 𝒫(Q × Γε)
Input: (state, letter or ε, top symbol or ε). Output: a SET of (new state, symbol to push or ε). A set, because PDAs are nondeterministic.
δ(q, a, c) = {(r1, d), (r2, e)}
In state q, reading a, popping c: either go to r1 and push d, or go to r2 and push e. Two copies.
Accept if some thread is in an accept state at the end of the input
Same rule as an NFA: one winning copy is enough. Acceptance is only checked at the end.

Example 1: D = {0k1k | k ≥ 0}

1) Read 0s, push each one, until a 1 comes
One plate per 0. q2 loop: 0, ε → 0.
2) Read 1s, pop one 0 for each
q2 → q3 and q3 loop: 1, 0 → ε. A 1 can only be read if a 0 is on top.
3) Accept if the stack is empty
q3 → q4: ε, $ → ε. Possible only if every 0 was matched. q1 is also accepting so that ε (k = 0) is accepted.

Example 2: B = {wwR | w ∈ {0,1}*}

wR = w written backwards
w = 011 gives wR = 110, so wwR = 011110. Sample input on the slide: 011110.
1) Read and push symbols; nondeterministically either repeat, or go to (2)
The machine does not know where the middle is. It GUESSES, by cloning: one copy keeps pushing, one copy moves to step 2. The ε, ε → ε arrow is that guess.
2) Read symbols and pop, compare. If ever ≠, that thread rejects
The stack gives the first half back in reverse order, exactly what wR needs.
3) Accept if the stack is empty
Pop $ with ε, $ → ε.
The nondeterministic forks replicate the stack

Lecture 09 · Context-free languages III: converting CFGs into PDAs

The PDA that pretends to be a grammar

Lecture 9 depends completely on Lectures 7 and 8. The idea is short: the stack holds what the grammar still has to produce.

Theorem

If A is a CFL, then some PDA recognizes A. Proof: convert A's CFG into a PDA. The PDA starts with the start variable and guesses substitutions, keeping the not-yet-finished string on the stack.

The first idea, and why it is cheating

Keep the whole intermediate string on the stack, e.g. E+T, then T+T×F, …
That is the derivation of a+a×a written as stacks.
Problem: to replace the T in "E+T" you would need to reach below the top
A PDA may only touch the top. Access below the top is cheating.
Fix: only substitute a variable when it is ON TOP. If a terminal is on top, pop it and compare it with the next input letter. Reject if ≠
Matching terminals as soon as they reach the top keeps the leftmost variable on top. This is exactly a leftmost derivation.

The construction in 3 rules

CFG → PDA
  1. Push $ and then the start symbol S (so S is on top).
  2. Repeat: if the top is a variable A, replace it with the right side of one of its rules (nondeterministic choice), with the first symbol on top. If the top is a terminal a, read a from the input and pop it; if the input letter is different, this copy dies.
  3. If the top is $ (the stack is otherwise empty), pop it and accept.
Diagram: qstart —ε,ε→S$→ qloop —ε,$→ε→ qaccept
"push S$" means push $ first and S second, so S ends on top.
On qloop: one loop "ε, A → w" for every rule A → w
Read nothing, pop the variable, push its right side.
On qloop: one loop "a, a → ε" for every terminal a
Read a and pop a: the matching step.
Pushing a whole string w = w1…wk uses extra states
A PDA arrow pushes one symbol. So the textbook figure pushes the LAST symbol first and the FIRST symbol last, through small helper states, so w1 ends on top.

b = length of the longest right-hand side of a rule

Each level multiplies the number of nodes by at most b.
Set p = b|V| + 1, with |V| = number of variables

|s| ≥ p > b|V| ⟹ bh ≥ |s| > b|V| ⟹ h > |V|
If h were ≤ |V|, there could be at most b|V| leaves, too few.
The longest path has at least |V| + 1 variables, so some R repeats
|V| + 1 variables but only |V| different ones.
Extra (from the textbook): why |vy| ≥ 1 and |vxy| ≤ p
Use the smallest possible parse tree, otherwise the pasting would give a smaller tree for s; so v and y are not both empty. Choose the repeat among the lowest |V| + 1 variables of the path, so the R-subtree is short and vxy has at most p letters.

Lecture 11 · Turing machines I: basics and formal definition

The machine with an endless notebook

A Turing machine is a finite automaton that can write on its tape and walk back and forth. That is all. With those two powers it can compute anything a real computer can.

In one sentence

A Turing machine reads a cell of a tape, writes a symbol there, moves one cell left or right, and changes state, again and again, until it enters qaccept or qreject (or runs forever).

The five assumptions (compare with DFA and PDA)

1) The head can read and write
A DFA only reads. A TM can overwrite a cell, for example cross a symbol off.
2) The head is two-way (left or right)
A DFA and a PDA only move right, one letter at a time. A TM can go back and re-read.
3) The tape is infinite (to the right)
Unlimited memory. A PDA also has unlimited memory, but only the top of the stack is reachable.
4) Infinitely many blanks ␣ follow the input
The input is written at the left end; every other cell starts as blank. Seeing ␣ means "past the end of the input".
5) It can accept or reject any time
A DFA decides only when the input runs out. A TM decides the moment it enters qaccept or qreject.

Example: B = {akbkck | k ≥ 0}

A PDA cannot do this one (Lecture 10 showed 0k1k2k is not context-free). A TM can, by crossing letters off.

1) Scan right until ␣ while checking the input is in a*b*c*; reject if not
First make sure the order is right: all a's, then b's, then c's.
2) Return the head to the left end
Walk left until the beginning.
3) Scan right, crossing off one a, one b and one c
One of each per trip. Crossing off = remembering "already counted".
4) If those were the last of each symbol, accept
All three ran out at the same time, so the counts were equal.
5) If it was the last of some symbol but not others, reject
One kind ran out first, so the counts were different.
6) If all symbols remain, return to the left end and repeat from (3)
Keep pairing them off, one trip per triple.
Check-in 5.2 — how do we "cross off"?

(b) We use a tape alphabet Γ = {a, b, c, ȧ, ḃ, ċ, ␣}: each letter has a "crossed" twin. Writing the twin = crossing off. No new feature or eraser is needed. Below the crossed letters are A, B, C.

This low-level machine checks the order while it crosses off, instead of in a separate first pass. Same language, fewer states. Any correct design gets the marks.

Formal definition: a 7-tuple

TM = (Q, Σ, Γ, δ, q0, qaccept, qreject)
Seven parts. Q, Σ, Γ are all finite sets.
Σ = input alphabet, not containing the blank ␣
The input itself never contains blanks, so the first ␣ marks its end.
Γ = tape alphabet, with ␣ ∈ Γ and Σ ⊆ Γ
The tape can hold input letters, the blank, and extra symbols like x or crossed letters.
δ : Q × Γ → Q × Γ × {L, R}
Given the state and the symbol under the head: the new state, the symbol to WRITE, and the direction to MOVE.
δ(q, a) = (r, b, R)
In state q reading a: write b over it, move right, go to state r.
q0 start, qaccept accept, qreject reject, with qreject ≠ qaccept
Exactly one accept state and one reject state, and they are different.
This model is deterministic
One output per (state, symbol). Check-in 5.3: to make it nondeterministic, change δ to δ : Q × Γ → 𝒫(Q × Γ × {L, R}) (answer b).

Three possible outcomes

1. Accept w: enter qaccept
The machine halts and says yes.
2. Reject w by halting: enter qreject
The machine halts and says no.
3. Reject w by looping: run forever
It never says yes, so it does not accept. But it never says no either. A DFA can never loop (the input ends); a TM can.

Configurations

Configuration = (current state, current tape contents, current head position)
A full snapshot of the machine at one moment. Knowing it, you know everything about what happens next.

The tape is uv, the state is q, and the head is on the FIRST symbol of v. So the state name is written just to the left of the cell being read.

L(M) = {w | M accepts w}; M recognizes A if A = L(M)
Same idea as for DFAs.
A is Turing-recognizable if A = L(M) for some TM M
For strings in A the machine says yes. For strings not in A it may say no OR loop forever.
M is a decider if M halts on all inputs
It never loops: always yes or no.

Two machines, step by step

Lecture 12 shows two textbook machines three ways: in words (implementation level), as a formal description, and as a state diagram. Run both here.

Three levels of describing a TM

Implementation-level description
Numbered English steps: how the head moves and what it writes. No states. ("Sweep left to right crossing off every other 0.")
Formal (low-level) description
The 7-tuple: Q, Σ, Γ, δ, start, accept, reject. δ is given by a state diagram or a table.
Arrow label a → b, R
Reading a, write b, move right. a → R is short for "reading a, leave it as it is, move right". Missing arrows go to qreject.

Example 2 (Sipser 3.7): A = {02n | n ≥ 0}

Strings of 0s whose length is a power of 2: 0, 00, 0000, 00000000, …

1. Sweep left to right across the tape, crossing off every other 0
Crossing off every second 0 cuts the number of 0s in half.
2. If in stage 1 the tape contained a single 0, accept
1 = 20 is a power of 2. We kept halving and reached exactly 1.
3. If in stage 1 the tape contained more than a single 0 and the number of 0s was odd, reject
An odd number bigger than 1 can never be a power of 2 (every power of 2 above 1 is even).
4. Return the head to the left-hand end of the tape
Get ready for the next sweep.
5. Go to stage 1
Halve again.
Q = {q1, …, q5, qaccept, qreject}, Σ = {0}, Γ = {0, x, ␣}
The formal description: x is the "crossed off" symbol.
q1 writes ␣ over the first 0
A trick: the blank marks the left end of the tape, so in q5 the machine knows when it has walked back far enough.
q3 and q4 alternate
q3 = "seen an odd number of 0s so far in this sweep", q4 = "even". q3 leaves a 0, q4 crosses one off: that is "every other 0". Hitting ␣ in q4 means odd count → reject.

Try 0000 and compare with the sample run on the slide: q1 0000, ␣q2 000, ␣xq3 00, ␣x0q4 0, ␣x0xq3 ␣, ␣x0q5 x␣, … ␣xxx␣qaccept.

Example 3 (Sipser 3.9): B = {w#w | w ∈ {0,1}*}

1. Zig-zag across the tape to corresponding positions on either side of #, checking they contain the same symbol. If not, or if there is no #, reject. Cross off symbols as they are checked
Take the first unchecked symbol on the left, remember it in the state (q2 = "it was 0", q3 = "it was 1"), walk past # to the first unchecked symbol on the right, compare, cross it off, walk back.
2. When all symbols left of # are crossed off, check for remaining symbols right of #. If any remain, reject; otherwise accept
q8: the right side must also be fully crossed off, else the right part was longer.
Σ = {0, 1, #}, Γ = {0, 1, #, x, ␣}
x again means crossed off.
The state remembers ONE symbol
A finite control cannot remember the whole w, but it can carry one symbol at a time across the tape. That is why we zig-zag.

Recipe: describe a TM

Recipe
  1. Find a "cross off and repeat" strategy: what do you mark in one trip?
  2. Write the implementation-level description as numbered steps, including when to accept and when to reject.
  3. Give each phase of a trip its own state: "looking for X", "carrying X to the right", "walking back".

Cheat sheet

DFA
(Q, Σ, δ, q0, F), δ: Q×Σ→Q. One arrow per state per letter. Regular = some DFA recognizes it. Complement: swap F. Product: pairs, ∪ = at least one accepts, ∩ = both, ⊖ = exactly one; k1k2 states.
NFA
δ: Q×Σε→𝒫(Q). Accept if some copy accepts. NFA→DFA: sets of states, start = E(q0), accept = sets containing an accept state, ∅ = dead. Up to 2n states.
Closure (NFA pictures)
∪: new start, ε to both. ∘: ε from N1's accepts to N2's start. *: new accepting start, ε to old start, ε from accepts back.
Regex
Order: * then ∘ then ∪. R∪∅=R, Rε=R, R∅=∅, ∅*=ε. GNFA elimination: r1r2*r3 ∪ r4. Two loops on one state: (r ∪ s)*.
Pumping (regular)
s=xyz, |xy|≤p, |y|≥1, xyiz∈A. Choose s starting with p copies of one letter ⟹ y = ak, 1≤k≤p. i=2 pump up, i=0 pump down. Closure trick: ∩ with a*b*. Finite ⟹ regular.
CFG
(V, Σ, R, S). Left side = one variable. Ambiguous = 2 parse trees = 2 leftmost derivations. Patterns: aSb, aSa|bSb|a|b|ε, S→S1|S2, S→S1S2.
PDA
(Q, Σ, Γ, δ, q0, F), δ: Q×Σε×Γε→𝒫(Q×Γε). "a,b→c" = read a, pop b, push c. Start ε,ε→$, end ε,$→ε. No middle marker ⟹ guess with ε,ε→ε.
CFG → PDA
Push S$. Top variable: replace by a rule's right side (first symbol on top). Top terminal: match input and pop. $ on top: accept. Trace table = leftmost derivation.
Pumping (CFL)
s=uvxyz, |vxy|≤p, |vy|≥1, uvixyiz∈A. Window anywhere ⟹ cases. 0p1p2p, 0p1p0p1p. p = b|V|+1. CFLs not closed under ∩.
Turing machine
(Q, Σ, Γ, δ, q0, qacc, qrej), δ: Q×Γ→Q×Γ×{L,R}. ␣∉Σ, ␣∈Γ, Σ⊆Γ. Outcomes: accept, reject, loop. Configuration u q v. Decider = halts on all inputs. Regular ⊂ CFL ⊂ decidable ⊂ recognizable.
